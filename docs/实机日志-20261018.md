## 5. 入站写入链路（上游 self-test，真实聊天行）

配置：`send_language=zh-CN`、`inbound_self=1`；玩家在游戏里输入 **英文** `need help`（不经过中文 IME）。

```
CHAT name="蓝牙一号" body="need help"
OWN message name="蓝牙一号" body="need help"
INBOUND self-test idx=2 translation="需要支援"
TRANSLATE ok tag=CN len=17 text="[CN] 需要支援"
INBOUND sig setter       rva=0x1441ca0 ...
INBOUND sig string_setter rva=0x143a1b0 ...
INBOUND guard rva=0x1860c49 match=true arg=0x110
INBOUND set idx=2 kind=final slot=2 off=+0x240 value=0x1befc92d834>0x7ec58820 want=0x7ec58820 len=22 err=nil
INBOUND height slot=2 17.0 -> 34.0 (lines=2 kind=final)
MSEND ok sent=3 "[CN] 需要支援"
```

玩家目视确认：`need help` 下面正常显示中文「需要支援」，字体正常。

这验证了入站最危险的一段：**按正文指针找到聊天行 → 调 setter 换缓冲区 → 把行高从 1 行撑到 2 行 → 中文正常渲染**。

## 5c. 输入法守护

游戏前台时：

```
before 0x8040804  (中文键盘布局)
after  0x4090409  (英文 US)
离开游戏后恢复 0x8040804
```

实现方式：`PostMessageW(hwnd, WM_INPUTLANGCHANGEREQUEST, 0, LoadKeyboardLayoutW("00000409"))`。
`ImmGetContext(游戏窗口)` 返回 NULL，IMM 转换模式那条路走不通。

## 5d. line 模式（最终采用）

截图确认：写回原行时，译文第二行会从**发送者名字下面**开始，看着偏左；因此默认改为本地独立一行。

```
INBOUND queued idx=0 from="FakePlayer" len=31
INBOUND translated idx=0 len=38 text="[EN] 前方接敌，现在需要支援"
INBOUND line ok=true reason=line text="[EN] 前方接敌，现在需要支援"
CHAT name="蓝牙一号" body="↳[EN] 前方接敌，现在需要支援"
```

玩家目视确认：「正常，就用这个」。游戏把这条本地消息当普通聊天行排版，对齐正常，且不会发给队友。
新版默认 `inbound_render=line`、`line_prefix=↳`（源码会补一个空格，显示为 `↳ [EN] ...`）。
